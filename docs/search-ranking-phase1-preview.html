Search Ranking Phase 1

検索対象は metadata のままにしつつ、タイトルと最初のプロンプトを分けて扱い、 「最初に何を頼んだか」に一致する session が上に来やすくなる変更です。

Schema FTS の列を ai_title, first_prompt, cwd に分離。
Ranking first_prompt の bm25 weight を強めに設定。
Compatibility CLI / TUI の出力形式と既存の boost は維持。

1. FTS の検索カラムを分離

以前は ai_title と first_prompt を結合した preview を FTS に入れていました。そのため、タイトル一致なのか、 最初のプロンプト一致なのかを ranking で区別できませんでした。

Before 
sessions_fts(
  preview,
  cwd
)
→
After 
sessions_fts(
  ai_title,
  first_prompt,
  cwd
)

2. first_prompt を強めに評価

検索時の bm25() に column weights を渡すようにしました。 これで、同じキーワードでも first_prompt に出てくる一致を より重要なヒットとして扱えます。 

bm25(sessions_fts, 1.5, 3.0, 0.8)
1.5 ai_title
3.0 first_prompt
0.8 cwd

3. 既存の score は維持

Rust 側の composite score はそのままです。current cwd の session を上げる boost と、最近の session を自然に上げる recency score は維持しています。 

score = -rank + cwd_boost * 2.0 + recency * 1.0

今回は FTS 側の metadata ranking を改善する Phase 1 なので、 本文検索、message table、snippet 表示は入れていません。

4. Schema version と trigger

FTS テーブル構造が変わったため、SCHEMA_VERSION を 4 から 5 に上げました。DB は cache 側だけを作り直し、 Claude Code の JSONL session ファイルには書き込みません。

insert / delete / update trigger も、新しい FTS columns に合わせて ai_title, first_prompt, cwd を同期します。

5. テストで確認したこと

  • FTS の columns が ai_title, first_prompt, cwd に分かれていること
  • cwd での検索が引き続き動くこと
  • metadata と cwd をまたいだ AND 検索が動くこと
  • first_prompt 一致が ai_title 一致より上位に来ること
